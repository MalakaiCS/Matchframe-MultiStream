First release (MVP) of MatchFrame Multistream: an OBS Studio plugin that sends the same finished
Program feed to up to eight RTMP/RTMPS destinations at once from one computer, using one shared
H.264 + AAC encoder pair. Built for **OBS Studio 32.2.2**.

This is a **pre-release**: it has passed the automated acceptance suites below, but has not yet been
used against real YouTube, Facebook, Twitch or Kick accounts, and the macOS package is not signed.

## What it does

* A dock (**Docks > MatchFrame Multistream**) with named destinations for YouTube, Facebook,
  Twitch, Kick or any custom RTMP/RTMPS server, several per platform if needed.
* Start Enabled Outputs / Stop All (with confirmation), per-destination start, stop, edit,
  duplicate and delete; live state, measured bitrate, elapsed time, dropped frames, reconnects and
  the last error for each destination; an upload estimate for the enabled destinations.
* One shared encoder pair for every destination (default H.264 6000 kbps CBR, 2 s keyframes,
  AAC 160 kbps, OBS audio track 1; hardware H.264 when OBS offers one, otherwise x264).
* Automatic reconnect after a lost connection (2, 4, 8, 16, then every 30 s, up to 20 attempts),
  independent of every other destination and of OBS's own streaming, recording and replay buffer.
* Stream keys and server passwords in Windows Credential Manager or the macOS Keychain — never in
  plugin files, logs, exports or diagnostics. Exports contain metadata only.
* Nothing starts on its own: not after OBS starts, after a crash, or after an import.
* "Sending to server" means the ingest server accepted the stream. Confirm each broadcast in the
  platform's dashboard.

## Verified for this release

Every check below ran automatically on the release commit; see
[docs/TESTING.md](https://github.com/MalakaiCS/Matchframe-MultiStream/blob/v0.1.0/docs/TESTING.md)
for the full record.

* **Windows** (GitHub Actions `windows-2025-vs2026`, VS 2026, MSVC 19.51): build with warnings as
  errors; unit tests including Windows Credential Manager; the release zip installed with its
  install script into the **official OBS Studio 32.2.2** build, whose dock was then driven through
  its widgets (add/edit/duplicate/delete, export/import, eight simultaneous destinations, Studio
  Mode, transitions, graphics, muting, native streaming/recording/replay buffer, profile switch,
  exit while live, keys restored from Credential Manager after a restart); uninstall and stored-key
  removal.
* **macOS** (GitHub Actions `macos-26`, Xcode 26.5): universal build with warnings as errors; unit
  tests including Keychain round trips; installer package built, inspected and installed with
  `installer`; stored-key removal. The real-OBS UI suite against the official OBS Studio 32.2.2
  Apple silicon build: RESULT PENDING (to be filled in before the tag is cut).
* **Linux** (test platform only): OBS 32.2.2 built from source; libobs integration tests against
  local RTMP/RTMPS receivers (shared encoder pair, eight outputs, receiver loss and reconnect,
  invalid key, refused connection, TLS failure, handshake stall, rapid start/stop, audio track and
  muting, native-output independence, verified RTMPS, A/V alignment versus OBS's own recording) and
  the real-OBS UI suite.
* **Soak**: 120 minutes, four destinations at 720p30 / 6000 + 160 kbps — all four sending
  throughout, 0 dropped frames, 0 reconnects, memory trend +1.76 MB/hour, no progressive A/V drift.

## Known limitations

* Not yet tested against real platform accounts (acceptance item 12).
* Hardware encoders (NVENC, Quick Sync, AMF, Apple VideoToolbox) were not exercised; CI machines
  have no GPU encoder, so every test used x264.
* The soak ran at 720p on a CPU-only virtual machine, not 1080p on target hardware.
* The macOS package is unsigned and not notarized.
* Linux is a test platform only: no Linux package, and keys are session-only there.
* One shared profile for all destinations; per-destination bitrates, resolutions or audio tracks
  are not part of this release.
