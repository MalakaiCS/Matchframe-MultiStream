MatchFrame Multistream 1.0.0: an OBS Studio plugin that sends the same finished Program feed to up
to eight RTMP/RTMPS destinations at once from one computer — for example YouTube and Facebook at the
same time — using one shared H.264 + AAC encoder pair. Built for **OBS Studio 32.2.2**.

The Windows, macOS and Linux checks under "Verified for this release" passed in CI on this exact
commit before the release was published. Still outside what the project could test: real YouTube,
Facebook, Twitch and Kick accounts, hardware encoders, and operator hardware. The macOS package is
unsigned.

## Upgrading from 0.1.0

Quit OBS, then install 1.0.0 the same way as 0.1.0. On Windows the install script replaces the old
plugin folder. On macOS the package installs into the same plugin folder; for a clean upgrade, first
run 0.1.0's `uninstall-matchframe-multistream.sh`, which removes only the plugin. Saved
destinations, encoding settings and stored keys are kept either way (the configuration format is
unchanged). Installing over 0.1.0 was not exercised separately in CI.

* Profiles whose names contain non-Latin letters get their own configuration file now (see below);
  the old file is moved over once and the dock shows a notice.
* The audio default is now 128 kbps. A profile saved by 0.1.0 keeps the 160 kbps it stored; set
  **Encoding > Audio bitrate** to 128 kbps if you stream to Facebook, which accepts at most 128.
* A Facebook destination with an `rtmp://` URL now shows an error: use Facebook's `rtmps://`
  server URL (port 443) from Live Producer.

## What it does

* A dock (**Docks > MatchFrame Multistream**) with named destinations for YouTube, Facebook,
  Twitch, Kick or any custom RTMP/RTMPS server, several per platform if needed.
* Start Enabled Outputs / Stop All (with confirmation), per-destination start, stop, edit,
  duplicate and delete; live state, measured bitrate, elapsed time, dropped frames, reconnects and
  the last error for each destination; an upload estimate for the enabled destinations.
* One shared encoder pair for every destination (default H.264 6000 kbps CBR, 2 s keyframes,
  AAC 128 kbps, OBS audio track 1; hardware H.264 when OBS offers one, otherwise x264).
* Automatic reconnect after a lost connection (2, 4, 8, 16, then every 30 s, up to 20 attempts),
  independent of every other destination and of OBS's own streaming, recording and replay buffer.
* Stream keys and server passwords in Windows Credential Manager or the macOS Keychain — never in
  plugin files, logs, exports or diagnostics. Exports contain metadata only.
* Nothing starts on its own: not after OBS starts, after a crash, or after an import.
* "Sending to server" means the ingest server accepted the stream. Confirm each broadcast in the
  platform's dashboard.

## Changes since 0.1.0

Fixes:

* **Crash when starting after an OBS video reset.** Changing OBS's video settings (or switching to
  a profile that resets video) and then starting a destination crashed OBS, because the shared
  encoders stayed bound to the video output OBS had just freed. Fresh encoders are now created for
  each start, as OBS does for its own outputs.
* **Stopping outputs** waits for OBS's RTMP output to finish with its stream before releasing it,
  so a stop can no longer free the stream while OBS's send thread is still using it.
* **Profile switch while live:** the plugin now allows 35 s (longer than the RTMP receive timeout)
  for its outputs to stop before OBS resets video for the new profile.
* **Non-Latin profile names:** profiles named with non-Latin letters all shared one configuration
  file, so they showed each other's destinations and overwrote each other's stored keys. Each now
  has its own file.
* **Read-only configuration** (written by a newer version, or unreadable): edits are refused
  instead of changing destinations whose keys the file still pointed to.
* A destination refused by the 32-destination limit no longer leaves its key in the secure store.

Platform compatibility (every RTMP/RTMPS server in OBS 32.2.2's own service list, 536 URLs across
84 services, is now checked by a unit test):

* Facebook destinations require `rtmps://`, as Facebook does.
* A pasted `{stream_key}` placeholder, and spaces or invisible characters (no-break and zero-width
  spaces copied from web pages) in the server URL or stream key, are rejected with a clear message
  instead of failing at the server. The editor trims surrounding whitespace.
* A custom server URL without an application path is a warning instead of an error; the named
  platforms still require one.
* Query parameters in a server URL are warned about, since OBS's RTMP output writes the full URL to
  the OBS log. YouTube's `?backup=1` is exempt and is now kept in exports, so an imported backup
  destination stays a backup stream.
* The "prefer rtmps://" hint is no longer shown for Twitch, whose dashboard has no ingest URL.

## Verified for this release

The Windows, macOS and Linux checks below ran in CI on the release commit; the release is only
published when all of them pass. The soaks ran separately on a Linux test VM. See
[docs/TESTING.md](https://github.com/MalakaiCS/Matchframe-MultiStream/blob/v1.0.0/docs/TESTING.md)
for the full record.

* **Windows** (GitHub Actions `windows-2025-vs2026`, VS 2026): build with warnings as errors; unit
  tests including Windows Credential Manager; the release zip installed with its install script
  into the **official OBS Studio 32.2.2** build, whose dock was then driven through its widgets
  (add/edit/duplicate/delete, export/import, eight simultaneous destinations, Studio Mode,
  transitions, graphics, muting, native streaming/recording/replay buffer, profile switch, exit
  while live, keys restored from Credential Manager after a restart); uninstall and stored-key
  removal.
* **macOS** (GitHub Actions `macos-26`, Xcode 26.5): universal build with warnings as errors; unit
  tests including Keychain round trips; installer package built, inspected and installed with
  `installer`; the same real-OBS UI suite against the official OBS Studio 32.2.2 Apple silicon
  build, with keys saved to and restored from the macOS Keychain; uninstall and stored-key removal.
* **Linux** (test platform only): OBS 32.2.2 built from source; libobs integration tests against
  local RTMP/RTMPS receivers (shared encoder pair, eight outputs, receiver loss and reconnect,
  invalid key, refused connection, TLS failure, handshake stall, rapid start/stop, audio track and
  muting, native-output independence, verified RTMPS, a video reset between two starts, A/V
  alignment versus OBS's own recording) and the real-OBS UI suite.
* **Soak** (Linux test VM, not in CI): 115 minutes on the 1.0.0 code, four destinations at
  720p30 / 6000 + 128 kbps — all four sending throughout, 0 dropped frames, 0 reconnects, memory
  trend +2.96 MB/hour after a warm-up in the first half hour, no progressive A/V drift (30.3 ms).
  The 0.1.0 soak (120 minutes, commit 4b9070d) gave the same results.

## Known limitations

* Not tested against real platform accounts (acceptance item 12): ingest, Go Live flows and
  platform-side bitrate or keyframe warnings are untested.
* Hardware encoders (NVENC, Quick Sync, AMF, Apple VideoToolbox) were not exercised; CI machines
  have no GPU encoder, so every test used x264.
* The soaks ran at 720p on a CPU-only virtual machine, not 1080p on target hardware.
* The macOS package is unsigned and not notarized.
* Linux is a test platform only: no Linux package, and keys are session-only there.
* One shared profile for all destinations; per-destination bitrates, resolutions or audio tracks
  are not part of this release.
